## 失败案例与明显误判

### 1（最严重）`test.jpg`：模型对一张**手掌照片**输出了完整高置信度人体骨架

这不是边缘案例，是彻底的假阳性。MediaPipe 在一张手部特写上返回了 33 个关键点，
并且置信度极高：

```
left_ear      ( 539.3, 750.3)  vis=0.996
right_ear     ( 584.6, 836.1)  vis=0.998
left_shoulder ( 534.4, 766.9)  vis=0.999
right_shoulder( 622.0, 900.5)  vis=1.000
```

叠加图 `overlays/test_overlay.png` 可以直接看到骨架被画在手掌上。

**加固前**，本应用照单全收，报出：

```
Shoulder height asymmetry   -56.77 deg  [pronounced]   ← 对一张手掌照片
```

根因：MediaPipe 的 `visibility` 估计的是**单个关键点是否被遮挡**，
不是「画面里有没有人」。它在这里毫无警示作用，不能用来挡假阳性。

**已修复**：新增 `check_plausibility()`，做两项人体比例校验——
躯干轴线相对铅垂线的倾角（上限 40°），以及头颈段/躯干长比值（人体常见 0.22–1.10）。
手掌图两项都不过（倾角 61.3°、比值 0.16），现在整图拒绝出数。
三张真人照片（比值 0.50 / 0.50 / 0.44，倾角均 < 4°）不受影响。

这只是降低明显假阳性，**不是人体检测器**，骨架轻微贴错它抓不到。

### 2 三项矢状面指标完全未经验证

任务书四项指标里有三项要求侧面照，而现有素材**一张侧面照都没有**，
所以「头前引角」「圆肩」「躯干矢状面对齐」在真实数据上**从未被验证过**。

做过的只有一次**代码路径冒烟测试**：强制 `view=side` 跑真实模型输出，
确认三项都能执行、无异常、无 NaN/inf。产出的数字是无意义的（输入是正面照），
仅证明代码跑得通。例如 `pose.jpg` 被强制按侧面算会得到矢状对齐 +44.73°，
纯属大弓步把两踝拉开造成的假象。

**这是当前最大的缺口。** 三项主要指标的正确性目前只有单元测试里的
合成坐标（解析可验证）在支撑，没有任何真实照片证据。

### 3 `portrait.jpg` 的「轻度倾向」是噪声

头肩特写被判 −3.78°、`mild`。这张图里人物本就是随意的摄影姿势，
不是标准站姿测量；且踝部 vis=0.003、髋部也只有 0.73–0.79，
身体根本不完整。合理性检查放行了它（躯干倾角只有 0.8°，比例正常），
说明**该检查挡不住「构图不合规但姿势正常」的照片**。

现状是这类图仍会出数。可考虑的加固：要求踝部可见才输出任何指标——
但那会顺带否掉 `business-person.png` 这类半身图，取舍留给产品决定。

### 4 两张图完全检测不到人体

`hand-woman-man.jpg`（640×317）与 `woman_hands.jpg`（640×960）返回空结果。
两张都是手部为主的照片，检测不到是**正确行为**——对比 `test.jpg` 可见，
模型对手部图像的表现并不稳定：有时正确地什么都不返回，有时编造一整副骨架。

### 5 视角判定启发式未经压力测试

`肩宽/躯干长` 阈值（侧面 ≤0.25、正面 ≥0.40）是目测拍定的。
7 张图全部落入「正面」，**侧面与斜侧两个分支从未被真实图片触发过**。
UI 提供了手动覆盖，因为这个启发式完全不可信。
