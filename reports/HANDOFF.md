## 项目与现状

姿态评估网页 Demo。上传一张全身照，叠加 MediaPipe Pose 的 33 个骨骼关键点，
输出四项姿态**参考读数**（头前引角 / 圆肩 / 躯干矢状面对齐 / 高低肩）。

仓库：`yiggeror/a-test-of-posture-judge`，分支 **`claude/posture-assessment-demo-q1x8nj`**
（所有开发和推送都在这个分支上，不要推别的分支）。

**一句话现状：工具本身基本可用，但它给出的判定不可信。**

像一个外壳做完的体温计——能读数、数字也显示得精确，但从没跟标准表对过
（不知道多少度算发烧），本身还有 ±4 度的抖动，而且插进土豆里也照样给读数。

粗略完成度：**代码 ~90%，结论可信度 ~20%。**

## 已经做完的

- Flask 单页应用跑通：上传 → 33 关键点 → 骨架叠加 → 四项读数 + 阈值判定 + 改善建议
- 几何运算正确，**37 项单元测试**（合成坐标解析验证）
- 视角自动判定（正面/侧面/斜侧），用躯干偏航角，真实数据验证过
- 假阳性防护：膝关节伸展、躯干倾角、多人检测、关键点出框、跨度与输出合理性上限
- 每项读数带不确定度 ±
- 许可证合规：只用 MediaPipe（Apache-2.0），未用 YOLO-pose / OpenPose
- 测试集 74 张（全 Pexels License，随仓库提交，逐张来源记录在
  `testdata/sources_full.csv`）

读 `reports/PHASE0.md`（环境探测）、`PHASE2.md`、`PHASE3.md`（两轮验证与失败案例）
可以了解全部细节，尤其是 **PHASE3**。

## 已经踩过的坑（重要，别重复劳动）

1. **开放图库刷不出正侧面全身中立站姿照。** 上一轮目视筛查约 1400 张 Pexels，
   P0 命中率约 **0.1%**。瓶颈是"耳朵必须可见"叠加"手臂不能遮挡躯干"——
   图库里的 "side view standing" 几乎全是叉腰、抱臂、扶墙、插兜、走路。
   Wikimedia Commons 筛了约 350 张，命中 **0**（且 `Category:Human posture` 与
   `Category:Full-length portrait photographs` 这两个分类根本不存在）。
2. **缩略图会系统性高估合格率。** "脚底在不在画面内"和"耳朵露没露"在 500px
   缩略图上看不出来——上一轮标为"强候选"的 7 张，拉到全分辨率后只剩 1 张。
3. **MediaPipe 的 `visibility` 不能用来判断"这是不是人"或"这个点位置对不对"。**
   已证实三例：一张手掌照、一张穿袜小腿特写都被贴上完整人体骨架；
   一张长发盖住耳朵的照片，ear 关键点落在头发上而 visibility 报 1.000，
   应用据此输出"头前引角 +25.39°，明显倾向"。
4. **直立的人像雕塑 / 人体模特 / 玩偶，用几何手段排除不了**——躯干竖直、
   膝关节伸展、比例正常，和真人一模一样。已经不再往上加启发式规则。
5. mediapipe 1.0.1 **移除了旧的 `mp.solutions.*` API**，网上教程大多失效。
6. mediapipe 的 wheel 即使只做 CPU 推理也链接 EGL/GLES，headless 容器需要
   `apt-get install libegl1 libgl1 libgles2`（`scripts/setup.sh` 已包含）。

## 唯一的卡点

**侧面照只有 2 张。**

四项指标里有三项只能用侧面照算。阈值（多少度算圆肩）全是拍脑袋定的，
想校准就得看一批真人照片的数值分布——2 张看不出任何分布。

这一条不解决，前面做得再好，工具的结论也没有意义。

## 你的环境与上一轮的不同

**上一轮的云端环境网络出口受限**：COCO、Wikimedia、Pexels、Unsplash 全部
被 egress 策略 403 拦截，只有 pypi、storage.googleapis.com 和
raw.githubusercontent.com 可达。测试图是靠另一个 Cowork 会话在外面找、
再手动传进来的。

**你的环境网络出口是开放的。** 这是主要变化，意味着很多上一轮做不到的事
现在可以直接做。但请注意：上面第 1 条的 0.1% 命中率是**内容层面的稀缺**，
不是网络限制造成的——网络通了不代表图就有了。

## 接下来做什么

**以下是判断题，不是任务清单。** 怎么权衡、先做哪个、要不要推翻我的判断，
由你决定。我把已知信息摆出来，不预设路径。

核心目标没变：**让这个工具的判定变得可信**。围绕它，目前开放的问题有：

- **侧面数据怎么搞到。** 图库这条路的产出率已经实测过了（见上）。
  你的网络是通的，可以自己重新评估这个结论，也可以考虑别的来源。
  另外两条从没试过的路：合成渲染（能拿到**真值**——真实照片里没人知道
  那个人的头前引角"真正"是多少度），以及请用户自己拍。
- **阈值怎么校准。** 拿到数据之后的事。也值得先想清楚"校准"在这里
  到底意味着什么——没有临床标注的话，能做到哪一步。
- **重复性完全空白。** 同一个人同一姿势拍多张，读数波动多大？
  这是判断工具可不可信的关键指标，现在一个数都没有。
- **雕塑/模特/玩偶的排除**，几何手段已经到头了。要不要上分类器，值得评估。
- 现有指标本身也有已知的设计问题，`README.md` 的"已知限制"和 `PHASE3.md`
  里都写了（比如头前引和圆肩其实不是独立指标）。

## 硬约束（这些不要破）

- 只用 **Apache-2.0 / MIT** 授权的模型。**禁止 YOLO-pose（AGPL-3.0）
  和 OpenPose（学术许可）**。
- **不得虚构关键点坐标、测试结果或数据来源。** 拿不到就说拿不到。
- 阈值常量必须带注释注明来源等级（现有三档：`guess` /
  `geometric-estimate` / `literature-adjacent`），**不确定就明说是猜的**，
  不要包装成有依据。
- 用户可见的判定措辞用「参考」「倾向」，**不用「诊断」**。
  这不是医疗器械。
- 报告失败案例和误判时要诚实，不要只报好消息。

## 上手

```bash
./scripts/setup.sh                                   # 系统库 + venv + 依赖 + 模型 + 测试
./.venv/bin/python -m pytest tests/ -q               # 应当 37 passed
./.venv/bin/python scripts/validate.py --dir testdata --save-overlays
./.venv/bin/python app.py                            # http://127.0.0.1:5000
```

`scripts/triage_images.py` 可以对候选图自动判 ACCEPT/REJECT 并统计是否达标
（退出码 0 = 达标）；`scripts/fetch_from_manifest.py` 按 CSV 批量下载。
两者的既有阈值同样是可以质疑的。

## 附：给人看的备注

这份交接刻意没有写成分步任务清单。上一轮的经验是，过细的规则反而会误事——
比如原先"手臂不能遮挡躯干"那条，字面执行会把一批实际可用的正面照筛掉
（高低肩只用左右肩峰两点，手插兜在几何上够不着）。实测之后才纠正过来。

所以交接里给的是**事实和约束**，路径留给接手方判断。
