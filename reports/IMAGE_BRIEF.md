## 任务：为姿态评估项目采集测试图片

我在开发一个基于 MediaPipe Pose 的姿态评估工具。代码已完成，但测试图片严重不足：
目前只有 1 张合格的正面全身照，**侧面照 0 张**。

工具的四项指标里有三项（头前引角、圆肩、躯干矢状面对齐）**只能用侧面照计算**，
所以这三项至今没有任何真实数据验证。**侧面照是本次采集的第一优先级。**

**你不需要访问任何代码仓库，也不需要运行任何代码。** 只要找图、存图、记来源。

### 数量目标

收回来的图会经过一道自动筛查，经验上**只有一半左右能通过**。
所以请按下表的 **"建议采集量"** 来收，不要只收到"目标量"就停。

| 优先级 | 类别 | 目标量 | 建议采集量 |
|--------|------|--------|------------|
| **P0** | **侧面全身站姿照** | 20 张 | **40 张** |
| P1 | 正面全身站姿照 | 15 张 | 30 张 |
| P2 | 负样本（见下） | 10 张 | 15 张 |
| 加分 | 同一人「正面+侧面」配对 | 5 对 | 有就收 |

### P0 侧面照要求（最关键，请逐条对照筛选）

必须全部满足：

1. **正侧面 90°**，不是斜侧 45°。判断方法：**两侧肩膀在画面上几乎重叠成一条线**；
   如果能同时清楚看到左右两个肩膀的轮廓，那就是斜侧，不要。
2. **全身入镜**：头顶到脚底全在画面内，且**人体高度占画面 55% 以上**。
   人站在远处、画面里一大半是背景的，不要。
3. **耳朵清晰可见、未被遮挡**。头发、帽子、兜帽、耳机、口罩挡住耳朵的**一律不要**——
   两项矢状面指标完全依赖耳部关键点，遮住了数值会**安静地失真而不报错**。
   这条是最常见的淘汰原因，请重点把关。
4. **自然站立**，双脚大致并拢或与肩同宽。**不要**瑜伽体式、弓步、跑跳、深蹲、
   走路中、倚墙、单脚站立等任何非中立站姿。
5. **手臂不遮挡躯干轮廓**，自然下垂在身侧最好。抱胸、叉腰、举手、插兜的不要。
6. **衣着贴身或轮廓清晰**。宽大外套、长裙、风衣会让髋部关键点漂移。
7. **相机大致与身体平行**，避免明显俯拍/仰拍（画面地平线明显倾斜的不要）。
8. **背景简单、光线均匀**，人物与背景有对比。
9. **分辨率短边 ≥ 480px**，越高越好。
10. **画面中只有一个人**。

正面照（P1）要求相同，仅第 1 条改为:**正对镜头**，双肩连线大致水平、
左右肩都清晰可见、身体不侧转。

### P2 负样本（用来验证防误判，越"像人又不是人"越好）

这类好找，请覆盖以下几类，各 2–3 张：

- **完全不是人体**：手部特写、脚部特写、雕像、人体模特、玩偶、动物。
  （已实测发现 MediaPipe 会对一张**手掌照片**输出置信度 1.0 的完整人体骨架，
  这类样本价值很高，请务必收够）
- **半身照 / 大头照**（踝部出画）
- **坐姿、躺姿、弯腰**的人
- **画面中有多个人**
- **耳部被帽子或头发完全遮住**的全身照

### 图源与授权

**只收开放授权的图片**，逐张记录来源与授权。

- 优先：Wikimedia Commons（CC0 / CC-BY / 公有领域）、Openverse、
  Pexels、Unsplash、Pixabay。
- 搜索词：`full body side view standing`、`side profile standing person`、
  `posture side view`、`man standing profile full length`、
  `woman standing side view full body`、`standing posture lateral view`、
  `人体 侧面 站姿`。
- Wikimedia Commons 分类：`Category:Standing`、`Category:Human posture`、
  `Category:Full-length portrait photographs`。**请选着装正常的照片。**
- **避免**研究专用许可的数据集（MPII、Human3.6M、3DPW 等限制转授权），
  以及任何需要签协议才能下载的数据集。
- **不要收儿童的照片。** 在有自由授权替代品时，避免可识别身份的私人照片。

### 交付方式（二选一，能给文件最好）

**方式 A（首选）：直接给图片文件**

按类别分三个文件夹：`side/`、`front/`、`negative/`，
外加一个 `sources.csv`，表头固定为：

```
filename,source_url,author,license
```

打包成 zip 给我即可。

**方式 B（拿不到文件时）：只给 `sources.csv`**

`source_url` 必须是**图片文件本身的直链**（结尾是 `.jpg`/`.png` 那种），
不是图片所在网页的地址。我这边有脚本按 CSV 批量下载。

### 交付时请一并说明

1. 各类别实际收了多少张
2. 哪一类最难找、卡在哪
3. 有没有哪些图你拿不准合不合格（列出来，我来判）

**请不要为了凑数放宽标准。** 一张不合格的侧面照对我是负价值——
它会混进验证集，让本来就没验证过的指标看起来"验证过了"。
宁可少交，也请在交付里说清楚缺口。

## 背景说明（给人看的，不用发给 agent）

### 为什么把筛查留在这边

原计划是让采集方直接跑仓库里的 `scripts/triage_images.py` 自检，退出码 0 才算完工。
查证后发现这条路大概率走不通：

- **anthropics/claude-code#84581（未解决）**：Cowork 云会话无法访问任何 GitHub
  仓库——repo API 一律 403（公开库也是）、`git clone` 因为禁用终端提示而失败、
  产品里也没有添加仓库的 UI 入口。
- 本会话的 `create_session` 接口文档也写明：环境解析到 Cowork 时 `source_url`
  会被忽略，即从这里也没法给它挂仓库。
- 退一步说，就算能连上，为了筛图去装 mediapipe + 系统 GL 库 + 下 46MB 模型权重，
  对一个"找图"任务也不合理。

所以现在的分工是:**采集方找图记来源 → 图进到仓库 → 这边跑筛查**。
采集方那份提示词里已经不含任何仓库依赖。

### 收回来之后怎么处理

拿到方式 A 的 zip，解压进 `inbox/`；拿到方式 B 的 CSV：

```bash
./.venv/bin/python scripts/fetch_from_manifest.py --csv sources.csv --out inbox
```

然后跑筛查（退出码 0 = 各类别都达标）：

```bash
./.venv/bin/python scripts/triage_images.py --dir inbox --manifest inbox/manifest.json
./.venv/bin/python scripts/triage_images.py --dir inbox --move-accepted testdata
./.venv/bin/python scripts/validate.py --save-overlays
```

`triage_images.py` 会自动挡掉：分辨率不足、踝部出画、人体占比过小、斜侧视角、
耳部可见度不足、以及合理性检查不通过的图，并把无人体/不合理的归到负样本。

**它有一个已知盲区**：耳部可见度用的是 MediaPipe 的 `visibility`，
那个值估计的是"模型认为该点是否被遮挡"，**不等于"耳朵真的露出来了"**——
我们手上那张戴帽子+口罩的照片，耳部 vis 仍然是 1.000。
所以 P0 侧面照最后仍需人眼扫一遍耳朵。这也是为什么提示词里把第 3 条单独强调。

### 为什么要 20 张而不是 5 张

现在的状态不是"数据少"，是"三项主要指标一次都没在真实图片上跑过"。
阈值是拍脑袋定的，只有拿到一批真实照片、看清数值的实际分布，才谈得上校准。
10 张以下看不出分布。

负样本单列，是因为验证时发现了真问题：MediaPipe 对一张手掌照片输出了
`visibility ≈ 1.0` 的完整 33 点骨架，应用照单全收报出"高低肩 −56.77°，明显倾向"。
已加人体比例合理性检查挡住这一例，但只有一例样本，
不知道这个检查是太松还是太紧——需要一批负样本才能调。

### 如果你哪天有 10 分钟

说句实话：**自己或找位同事用手机拍 6 张，价值高于网上找 50 张。**

手机架在椅子上（别手持），距离 2–3 米，镜头高度大约在髋部，穿贴身衣服，
然后正面 1 张、左侧面 1 张、右侧面 1 张，再把同样的姿势重复拍 3 遍。

这 6 张能给到网图给不了的三样：**配对的正侧面**（同一人同一时刻）、
**重复性数据**（同姿势多张之间数值波动多大——这是判断工具可不可信的关键，
现在完全空白）、**已知的拍摄条件**（相机高度距离已知，可反推透视误差）。
网图永远给不了这三样，因为你不知道人家是怎么拍的。

### 还有一条路：合成图

真实侧面照实在难找的话，可以用 Blender + 免费绑定人体模型，
把关节摆到**已知角度**再渲染侧面图。这是唯一能拿到**真值**的办法——
真实照片里没人知道那个人的头前引角"真正"是多少度，
合成图你设的是 20° 就是 20°，可以直接验证几何算得对不对。

代价是验证不了真实世界的鲁棒性（光照、衣物、遮挡、体型差异），
所以是补充，不能替代真实照片。要走这条路我可以另外写脚本。
